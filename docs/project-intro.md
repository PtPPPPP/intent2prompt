# Intent2Prompt 项目介绍

> 面向中文学生创新场景的「意图 → 提示词」编译器。

---

## 一句话介绍

Intent2Prompt 不是简单的提示词美化工具，而是一个面向中文学生创新场景的"意图到提示词编译器"。系统通过**意图解析、缺失信息检测、结构化 Prompt 编译、质量评估和提示词资产管理**，降低普通用户使用 AI 的表达门槛。

输入一句模糊的中文想法，例如"帮我写一个挑战杯项目计划书"，系统会自动识别任务类型、补全关键缺口，并编译出 3 个可直接复制使用的 Prompt 版本，同时给出 7 维度的质量评分。

---

## 项目背景

AI 大模型已经进入每一个学生的日常：写项目计划书、做招新文案、读论文、做问卷、拆需求、做 PPT。但真正决定 AI 输出质量的，不是模型本身，而是**用户能不能把想法说清楚**。

我们观察到两个普遍现象：

1. **会用的同学和不会用的同学差距越来越大**。会用的人把 AI 当成高效助手，不会用的人只能得到泛泛而谈、格式混乱、无法直接使用的回答。
2. **校园创新场景的"通用提示词"基本不存在**。网上流传的 Prompt 模板多为英文、面向通用任务，难以直接套用到挑战杯、大创、社团招新、课程论文等中文学生场景。

Intent2Prompt 想解决的问题正是：**让一个只会说"帮我写个计划书"的同学，也能稳定地得到高质量、结构化、可继续修改的 AI 输出**。

---

## 用户痛点

| 痛点 | 具体表现 | 后果 |
| --- | --- | --- |
| 表达模糊 | 只会说"帮我写一个 XX" | AI 自由发挥，输出跑偏 |
| 信息缺失 | 不知道该告诉 AI 什么 | 生成内容缺关键背景，不可用 |
| 没有结构 | 缺乏角色、格式、约束要求 | 结果格式混乱、需要大量返工 |
| 不会追问 | 不会反问 AI 还需要什么 | 一次性生成，难以迭代 |
| 害怕瞎编 | 涉及数据、论文、政策 | AI 编造数据，材料不敢直接用 |
| 不会复用 | 每次都从零写 Prompt | 重复劳动，质量不稳定 |

一句话总结：**用户的"意图"是清晰的，但转化成"高质量 Prompt"的门槛太高**。

---

## 解决方案

Intent2Prompt 把"写 Prompt"这件事，从一项**手艺活**变成一道**编译流程**。用户只需输入一句中文意图，系统会像编译器一样，依次完成：

1. **意图解析（Intent Analysis）**：识别任务类型、推断目标、抽取已知线索，并给出置信度。
2. **缺失信息检测（Missing Info Detection）**：按任务类型匹配规则，找出"用户没说但很关键"的信息。
3. **追问生成（Clarifying Questions）**：把缺失信息转成最多 3 条自然语言问题，引导用户补充。
4. **结构化 Schema 构建（Schema Building）**：把上述结果组装成统一的 `PromptSchema`（角色 / 任务 / 背景 / 输入 / 约束 / 输出格式 / 质量标准 / 默认假设 / 安全说明）。
5. **三版本 Prompt 编译（Prompt Compilation）**：基于同一份 Schema，编译出简洁版 / 专家版 / 比赛项目版。
6. **质量评估（Prompt Evaluation）**：用 7 个维度、满分 100 分的规则评分，给出优势、不足和改进建议。
7. **资产管理（Asset Management）**：通过浏览器本地历史记录，保存最近 6 条意图，方便复用。

---

## 核心流程

```text
用户输入一句中文意图
        │
        ▼
① 意图解析 analyzeIntent        ──> 任务类型 + 目标 + 已知信息 + 置信度
        │
        ▼
② 缺失信息检测 detectMissingInfo ──> 关键缺口列表（最多 6 条）
        │
        ▼
③ 追问生成 generateClarifyingQuestions ──> 最多 3 条自然语言问题
        │
        ▼
④ Schema 构建 buildPromptSchema  ──> 统一结构化中间表示
        │
        ▼
⑤ Prompt 编译 compilePromptVersions ──> 简洁版 / 专家版 / 比赛项目版
        │
        ▼
⑥ 质量评估 evaluatePrompt        ──> 7 维度评分 + 改进建议
        │
        ▼
⑦ 前端展示 + 一键复制 + 本地历史
```

> 对应代码入口：`lib/intentAnalyzer.ts` 的 `generatePromptPackage()`，后端接口 `POST /api/generate`。

---

## 核心功能

1. **中文短意图识别**：基于规则关键词 + 任务模板双重匹配，识别 11 类任务，返回置信度。
2. **缺失信息检测**：每个任务类型有专属规则，定位"没说但关键"的信息，最多列出 6 条。
3. **最多 3 个关键追问**：把缺失信息翻译成口语化问题，并按任务类型加上场景化开头。
4. **三版本 Prompt 编译**：
   - **简洁版**：快速复制，重点清楚。
   - **专家版**：完整结构（角色 / 任务 / 背景 / 输入 / 输出格式 / 约束 / 质量标准 / 默认假设 / 追问）。
   - **比赛 / 项目版**：在专家版基础上叠加比赛强化要求，适合挑战杯、大创、路演。
5. **Prompt 质量评分**：7 维度、100 分制，明确优势、不足和下一步建议。
6. **历史记录与复制**：localStorage 保存最近 6 条意图，每版 Prompt 支持一键复制。
7. **防幻觉设计**：缺失信息用 `【待补充：xxx】` 显式占位，绝不假装已经知道；涉及数据 / 论文 / 政策时强制标明来源。

## 项目亮点

- **定位独特**：不是"提示词润色器"，而是"意图到提示词的编译器"，强调**结构化中间表示（PromptSchema）**这一核心抽象。
- **闭环完整**：意图解析 → 缺失检测 → 追问 → Schema → 三版本编译 → 评分，一条流水线覆盖从"想法"到"可用 Prompt"全过程。
- **中文学生场景优先**：11 类任务模板全部针对挑战杯、大创、社团、论文、问卷等校园场景定制，内置 10 条中文测试样例。
- **可解释、可复现**：分类、缺失检测、评分全部基于规则，结果稳定可解释，方便答辩时逐条讲清"为什么这么生成"。
- **防幻觉优先**：缺失信息显式占位 + 安全说明，让生成结果"敢直接用、敢交给老师"。
- **零门槛演示**：默认 `LLM_PROVIDER=mock`，无需任何 API Key 即可跑通完整流程；同时保留 DeepSeek 等真实模型接入入口。

## 当前 MVP 能力

**已覆盖 11 类任务类型**：项目策划、商业计划、PPT / 演示、调查问卷、论文、代码、数据分析、社团运营、学习、写作、其他。

**已实现的能力**：

- 规则 + 模板双重意图识别，返回置信度（最高 0.95）。
- 每类任务的缺失信息规则与追问话术。
- 统一 `PromptSchema` 中间表示。
- 简洁版 / 专家版 / 比赛项目版三版本编译。
- 7 维度、100 分制规则评分。
- localStorage 历史记录（最近 6 条）。
- `data/examples.ts` 内置 10 条中文测试样例，并标注期望任务类型与关键缺失信息。
- Vitest 单元测试覆盖端到端流程（`tests/generate.test.ts`）。

**技术栈**：Next.js（App Router）+ TypeScript + React + Tailwind CSS + Next.js API Routes + Vitest。

## 后续方向

- **追问二次生成**：支持用户填写追问答案后重新编译 Prompt，形成"意图 → 追问 → 补全 → 再编译"闭环。
- **资产升级**：把历史记录从 localStorage 升级为可检索的提示词资产库（如 SQLite）。
- **真实模型按需介入**：让真实 LLM 只在低置信度或最终润色阶段介入，平时保持规则引擎的稳定与低成本。
- **更多学生场景模板**：扩展竞赛答辩稿、奖学金申请、实习简历、课程设计报告等模板。
- **评分可视化与对照**：把"原始短 Prompt"和"编译后 Prompt"的输出做 A/B 对照展示，直观证明价值。
