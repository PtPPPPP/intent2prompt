# Intent2Prompt 现场演示脚本

> 适用：3–5 分钟学生社团展示、挑战杯 / 创新创业比赛前期答辩。
> 演示案例：`帮我写一个挑战杯项目计划书`
> 建议环境：提前 `npm install && npm run dev`，打开 http://localhost:3000 ，确保默认 `LLM_PROVIDER=mock`（无需 API Key）。

## 一、开场介绍（建议口播）

> 大家好！我是 \_\_\_，今天给大家演示一个我们做的小工具，叫 **Intent2Prompt**。
>
> 它要解决的是一个几乎每个同学都遇到过的问题：**我们都知道 AI 很强，但很多人就是"用不好"它。** 问题往往不在 AI，而在于我们**说不清楚自己到底想要什么**。
>
> Intent2Prompt 不是又一个"提示词润色工具"。它是一个面向中文学生创新场景的**"意图到提示词编译器"**——你只要输入一句话的想法，它就能像编译器一样，把你的模糊意图，编译成一整套结构化、可以直接用的提示词。

*(一句话点题：从"想法"到"高质量 Prompt"，中间那道坎，Intent2Prompt 帮你跨过去。)*

---

## 二、痛点说明（建议口播）

> 举个最常见的例子：挑战杯要交项目计划书，很多同学第一反应是打开 AI，直接输入——

**在大屏上敲入这一句（先不要点生成）：**

```text
帮我写一个挑战杯项目计划书
```

> 看起来没问题对吧？但其实这句话至少有 5 个关键信息是**缺失**的：项目到底做什么主题？报哪个赛道？最大创新点是什么？有没有调研数据？要写多少字？
>
> AI 拿到这么模糊的需求，只能**自由发挥**——结果就是给你一篇空话套话、格式混乱、数据全是编的、根本不敢交上去的东西。
>
> 这就是普通同学用 AI 的真实困境：**意图是清楚的，但转化成高质量提示词的门槛太高。**

## 三、输入短意图（现场操作）

**点击「生成」按钮。**

*(等待结果渲染：意图解析卡 → 追问卡 → 评分卡 → 三版 Prompt 卡，从上到下依次出现。)*

> 注意，输入还是这一句话，**一个字都没多打**，但系统帮我们做了大量工作。

## 四、展示意图解析（指向「意图解析」卡片）

> 第一张卡是**意图解析**。系统判断这是一个**「项目策划」类任务**，置信度 **0.95**，非常高。
>
> 它还自动推断出了三件事：
> - **目标**：把项目想法整理成可申报、可执行、可继续扩写的项目材料。
> - **目标产物**：一份结构清晰、可继续扩写的项目计划书框架。
> - **已知信息**：它识别出这句话里"包含学生竞赛或创新项目场景"。

> *(强调点：系统不是简单做关键词匹配，而是给出了置信度，并且把已知线索抽出来了。这背后是规则 + 模板双重识别，11 类任务模型。)*

---

## 五、展示缺失信息（指向「意图解析」卡片的缺失信息区）

> 最关键的是这里——**缺失信息检测**。系统列出了 5 条我们没说、但对计划书很关键的信息：

```text
• 项目主题        （项目具体做什么？）
• 参赛方向        （报哪个赛道？）
• 核心创新点      （最大创新点是什么？）
• 数据支撑        （有没有调研或数据？）
• 篇幅要求        （大概要多少字？）
```

> 这就是 Intent2Prompt 和"直接问 AI"最大的区别：**它能告诉你，你漏了什么。**
>
> 而且系统做了一个很重要的设计：这些缺失信息，**绝不假装知道**。在生成的 Prompt 里，它们会被标成 `【待补充：项目主题】` 这样的占位符，而不是让 AI 瞎编一个。

> *(强调点：防幻觉。比赛材料最怕数据造假，这个设计让学生"敢直接用、敢交给老师"。)*

---

## 六、展示追问问题（指向「追问问题」卡片）

> 缺失信息太专业，普通同学不一定知道怎么补。所以系统进一步把它们翻译成**最多 3 条、口语化的追问**：

```text
1. 为提高项目材料质量，项目具体做什么？
2. 为提高项目材料质量，参加哪个赛道？
3. 为提高项目材料质量，最大创新点是什么？
```

> 注意每条问题前面都有一个**场景化开头**"为提高项目材料质量"。不同任务类型，开头不一样——社团运营是"为让社团内容更可执行"，论文是"为避免论文总结失真"。
>
> 这一步把系统从"单次生成"升级成了**"对话式引导"**：用户回答这 3 个问题，Prompt 质量会再上一个台阶。

---

## 七、展示三版 Prompt（指向下方三张 Prompt 卡片）

> 最后，系统基于一份统一的**结构化中间表示**，编译出**三个版本**的 Prompt。我们看专家版的结构：

```text
角色设定 Role            你是一名熟悉挑战杯、大创…的项目策划顾问。
任务目标 Task           帮助用户完成"…挑战杯项目计划书"：把项目想法整理…
背景信息 Context         用于挑战杯、大创…申报。缺失信息不能暗自编造。
输入材料 Input          帮我写一个挑战杯项目计划书
输出格式 Output Format   项目背景 / 痛点分析 / 目标用户 / 解决方案 / 创新点 / 实施计划 / 预期成果
约束条件 Constraints     紧扣评审标准，不写空泛口号；不编造数据…
质量标准 Quality Criteria 逻辑闭环 / 创新点明确 / 学生团队可执行…
默认假设 Assumptions     暂未提供「项目主题」，请用【待补充：项目主题】标出…
需要时的追问 Clarifying Q  …
```

> 三个版本各有侧重：
> - **简洁版**：几行话，快速复制，重点清楚。
> - **专家版**：完整结构，约束和质量标准齐全，追求高质量输出。
> - **比赛 / 项目版**：在专家版基础上，额外叠加"明确问题、对象、方案、创新点和可执行计划"等**比赛强化要求**，专门为挑战杯、路演这种场景设计。
>
> *(现场操作：点一下任意一版的「复制」按钮，展示一键复制。)*

> *(强调点：同一份意图、三个版本，对应不同使用场景；比赛版是面向我们学生竞赛场景的定制卖点。)*

## 八、展示评分（指向「质量评分」卡片）

> 系统还会给这套 Prompt 打分，7 个维度、满分 100 分：

| 评分维度 | 满分 | 示例分项 | 说明 |
| --- | --- | --- | --- |
| 任务清晰度 taskClarity | 20 | ~16 | 任务目标和输入是否清楚 |
| 背景完整度 contextCompleteness | 15 | ~7 | 背景、假设、追问是否齐全（缺口多会被扣分） |
| 输出格式清晰度 outputFormatClarity | 15 | ~13 | 输出结构是否明确 |
| 约束质量 constraintQuality | 15 | ~12 | 约束是否具体、有否定约束 |
| 可执行性 executability | 15 | ~8 | AI 是否能照着做（缺口多会被扣分） |
| 幻觉风险控制 hallucinationRiskControl | 10 | ~9 | 是否防编造、标来源 |
| 中文表达质量 chineseExpressionQuality | 10 | ~10 | 是否中文友好 |
| **合计** | **100** | **~75** |  |

> 注意：评分器是**诚实**的，不是无脑给高分。本案例识别出 5 条缺失信息，所以"背景完整度"和"可执行性"被合理扣分，综合约 **75 分**（满分 100，达标线 70）。系统会明确指出不足——**"关键信息缺口较多，建议先补充追问答案"**——并给出建议"先补充追问答案，再重新生成 Prompt"。
>
> *(强调点：这正是 Intent2Prompt 的核心价值闭环——评分不是为了好看，而是为了指出缺口、引导用户补全。回答完 3 条追问、补全 `【待补充】` 后再生成，分数会进一步提升。)*

## 九、总结项目价值（收尾口播）

> 我们回到最开始。同样一句"帮我写一个挑战杯项目计划书"：
>
> - 直接问 AI → 得到一篇空话套话、数据乱编、不敢用的草稿。
> - 经过 Intent2Prompt → 得到一份**任务清晰、信息完整、防幻觉、带追问、可评分**的专业提示词。
>
> **Intent2Prompt 的价值，不在于"把话说漂亮"，而在于把"写好提示词"这件本来靠经验的手艺活，变成了一条人人可用的标准流水线。**
>
> 它降低的是普通同学用好 AI 的表达门槛，让每一个只会说"帮我写一个 XX"的同学，都能稳定拿到高质量、结构化的 AI 输出。
>
> 这就是我们做 Intent2Prompt 的初衷。谢谢大家！

## 附：答辩常见问题（备答）

- **Q：它和 ChatGPT 自带的"提示词"有什么区别？**
  A：它针对中文学生竞赛场景做了 11 类任务模板，能检测缺失信息、生成追问、做多版本编译和质量评分，是一套"编译流水线"，而不是一句通用提示词。

- **Q：现在要不要 API Key / 要不要联网？**
  A：不需要。默认 `mock` 模式本地即可完整演示，规则引擎稳定可复现；也保留了 DeepSeek 等真实模型接入入口。

- **Q：评分会不会虚高？**
  A：不会。评分基于 7 个维度的规则量化，每分都有明确来源，可逐条解释；它还会因为缺失信息多而**主动扣分**——本案例 75 分正是因为 5 条缺口拉低了"背景完整度"和"可执行性"，并给出"先补全追问答案、再重新生成"的改进建议。

- **Q：数据会不会被 AI 编造？**
  A：不会。缺失信息一律用 `【待补充】` 占位，并强制要求涉及数据 / 论文 / 政策时标明来源和不确定性。
