# Intent2Prompt 对比样例（原始 Prompt vs 编译后 Prompt）

> 本文档用 3 组真实场景，对比"直接问 AI 的短 Prompt"和"经 Intent2Prompt 编译后的结构化 Prompt"。
> 每组包含：原始短 Prompt、原始 Prompt 的问题、Intent2Prompt 生成后的结构、优化后的优势、适合展示时强调的点。
> 表格 + 分段结合，方便答辩、路演、README 直接复用。

---

## 对比一：挑战杯项目计划书

### 基本判定

| 项 | 值 |
| --- | --- |
| 输入意图 | 帮我写一个挑战杯项目计划书 |
| 识别任务类型 | 项目策划 `project_planning` |
| 置信度 | 0.95 |
| 检测到的缺失信息 | 项目主题、参赛方向、核心创新点、数据支撑、篇幅要求 |
| 自动追问（最多 3 条） | 项目具体做什么？ / 参加哪个赛道？ / 最大创新点是什么？ |
| 生成的 Prompt 版本 | 简洁版 / 专家版 / 比赛项目版 |

### 原始短 Prompt

```text
帮我写一个挑战杯项目计划书
```

### 原始 Prompt 的问题

| 问题 | 后果 |
| --- | --- |
| 没说项目主题和赛道 | AI 随便编一个方向，跟你的真实项目无关 |
| 没说创新点 | 写成"放之四海而皆准"的套话 |
| 没说数据来源 | AI 编造调研数据，交上去有学术风险 |
| 没说格式和篇幅 | 结构混乱、字数失控 |
| 没有角色和约束 | 输出口吻不像项目材料，像百科介绍 |

### Intent2Prompt 生成后的结构（专家版 / 比赛版骨架）

```text
角色设定 Role           你是一名熟悉挑战杯、大创…的项目策划顾问。
任务目标 Task          帮助用户完成"…挑战杯项目计划书"：把项目想法整理成可申报…
背景信息 Context        用于挑战杯、大创、科研训练或校园创新项目申报；缺失信息不能暗自编造。
输入材料 Input         帮我写一个挑战杯项目计划书
输出格式 Output Format  项目背景 / 痛点分析 / 目标用户 / 解决方案 / 创新点 / 实施计划 / 预期成果
约束条件 Constraints    紧扣评审标准不写空话；突出问题对象方案创新点；数据用【待补充】占位不编造
质量标准 Quality Criteria 逻辑闭环 / 创新点明确 / 学生团队可执行 / 适合继续补材料
默认假设 Assumptions    暂未提供「项目主题」请用【待补充：项目主题】标出…
```

> **比赛 / 项目版**还会追加："明确问题、对象、方案、创新点和可执行计划；用学生项目能理解和复用的语言表达；缺失数据和背景只给占位符，不编造。"

### 优化后的优势

1. **角色到位**：直接把 AI 设定为"挑战杯项目策划顾问"，口吻和专业度立刻拉满。
2. **缺口可见**：5 条缺失信息全部显式标出，不会"假装知道"。
3. **结构对标评审**：输出格式按"问题—对象—方案—创新点—计划—成果"组织，正好对齐挑战杯评审逻辑。
4. **防幻觉**：数据和政策用 `【待补充】` 占位，杜绝编造。
5. **可迭代**：3 条追问引导用户补全，回答后可再编译。

### 适合展示时强调的点

- "同一句话，AI 直接给的是空话套话，我们给的是**对标评审标准的专业框架**。"
- "缺失信息会**显式占位**，不会让 AI 瞎编数据——这是竞赛材料最关键的安全线。"

## 对比二：AI 编程社团招新文案

### 基本判定

| 项 | 值 |
| --- | --- |
| 输入意图 | 帮我做一个 AI 编程社团的招新文案 |
| 识别任务类型 | 社团运营 `club_operation`（注意：输入同时含"编程""文案"，系统能正确区分） |
| 置信度 | 0.95 |
| 检测到的缺失信息 | 目标人群、发布平台、文案风格、报名方式（社团名称"AI 编程社团"已被识别为已知） |
| 自动追问（最多 3 条） | 主要面向谁？ / 发在哪个平台？ / 希望什么风格？ |
| 生成的 Prompt 版本 | 简洁版 / 专家版 / 比赛项目版 |

### 原始短 Prompt

```text
帮我做一个 AI 编程社团的招新文案
```

### 原始 Prompt 的问题

| 问题 | 后果 |
| --- | --- |
| 没说目标人群 | 不知道是写给大一新生还是全校同学，语气拿不准 |
| 没说发布平台 | 公众号、小红书、海报、群发的写法完全不同 |
| 没说文案风格 | AI 默认"正式官方腔"，招新文案却需要活泼、有钩子 |
| 没说报名方式 | 文案写完了，读者不知道怎么加群报名 |
| 缺少结构引导 | 容易写成一大段流水账，没有标题、亮点、行动号召 |

### Intent2Prompt 生成后的结构（社团招新模板）

```text
角色设定 Role           你是一名懂校园社团传播的新媒体文案策划。
任务目标 Task          把校园社团需求整理成可发布、可执行的运营内容。
输出格式 Output Format  标题 / 开头钩子 / 核心亮点 / 适合人群 / 内容结构或活动流程 / 行动号召
约束条件 Constraints    语言自然有校园感；突出参与理由、社团亮点和行动路径；保留可替换的信息占位符
质量标准 Quality Criteria 有吸引力 / 信息清楚 / 适合学生阅读 / 可直接发布、执行或改写
默认假设 Assumptions    暂未提供「目标人群」请用【待补充：目标人群】标出…
```

### 优化后的优势

1. **多关键词冲突下仍判对**：输入同时命中"编程（代码类）""文案（写作类）""社团（社团运营类）"，系统按优先级正确锁定为**社团运营**。
2. **平台适配意识**：追问"发在哪个平台"，让文案从一开始就考虑公众号 / 小红书 / 海报的差异。
3. **招新转化结构**：输出格式自带"开头钩子 → 核心亮点 → 适合人群 → 内容结构或活动流程 → 行动号召"，是一条完整的**转化漏斗**。
4. **占位符保护**：社团名、二维码、群号等留作占位，文案可直接发布、改完即用。

### 适合展示时强调的点

- "这一句同时有'编程''文案''社团'三个方向的词，系统能**准确判断这是社团招新**，而不是编程任务或普通写作。"
- "它还追问'发在哪个平台'——招新文案发公众号和发小红书，是两篇完全不同的东西。"

## 对比三：具身智能论文总结

### 基本判定

| 项 | 值 |
| --- | --- |
| 输入意图 | 帮我总结一篇关于具身智能的论文 |
| 识别任务类型 | 论文 `academic_paper` |
| 置信度 | 0.95 |
| 已抽取的已知线索 | 论文主题线索：**具身智能** |
| 检测到的缺失信息 | 学科领域、总结用途、希望深度、是否需要批判性评价、论文标题或材料 |
| 自动追问（最多 3 条） | 属于哪个领域？ / 用于汇报还是精读？ / 要简读还是深读？ |
| 生成的 Prompt 版本 | 简洁版 / 专家版 / 比赛项目版 |

### 原始短 Prompt

```text
帮我总结一篇关于具身智能的论文
```

### 原始 Prompt 的问题

| 问题 | 后果 |
| --- | --- |
| 没给论文原文 / 链接 | AI 根本没见过这篇论文，只能凭"具身智能"四个字**编**内容 |
| 没说总结用途 | 课堂汇报和精读笔记的详略、结构完全不同 |
| 没说深度 | 不知道要一句话概括还是逐段精读 |
| 没说是否要评价 | 不知道要不要写优缺点、局限性 |
| 缺少防幻觉约束 | AI 会把"想象中的论文"当成真论文讲，严重误导 |

### Intent2Prompt 生成后的结构（论文总结模板）

```text
角色设定 Role           你是一名严谨的学术阅读助理，擅长把论文拆成可理解的结构。
任务目标 Task          把论文材料整理成结构化总结，帮助理解和汇报。
输出格式 Output Format  一句话概括 / 研究问题 / 方法 / 核心结论 / 贡献 / 局限 / 可延伸问题
约束条件 Constraints    区分原文信息和个人推断；不编造论文内容和实验结果；保留不确定点并提醒补充原文
质量标准 Quality Criteria 准确 / 层次清楚 / 术语解释友好 / 便于汇报
默认假设 Assumptions    暂未提供「论文标题或材料」请用【待补充：论文标题或材料】标出…
安全说明 Safety Notes   涉及数据、论文、政策或事实判断时，必须标明来源和不确定性。
```

### 优化后的优势

1. **已知线索自动抽取**：从"关于 X 的论文"里抽出主题"具身智能"，作为上下文喂给 AI。
2. **学术级防幻觉**：约束里明确"区分原文信息和个人推断""不编造论文内容和实验结果"，这是论文场景的命门。
3. **结构对标汇报**：输出格式正好是论文汇报的标准结构（问题—方法—结论—贡献—局限—延伸），课堂直接能用。
4. **用途驱动追问**：通过"汇报还是精读""简读还是深读"决定详略，避免千篇一律。
5. **强制安全说明**：涉及事实判断必须标明来源和不确定性，让总结"敢交给老师"。

### 适合展示时强调的点

- "AI 没看过这篇论文，直接问它就是**学术造假现场**。我们的系统第一步就把'论文原文材料'列为缺失信息并占位，逼着用户先补材料。"
- "约束里写死了**区分原文和推断、不编造实验结果**——这是论文总结场景最不能踩的雷。"

## 横向对比总结

| 维度 | 直接用短 Prompt | 经 Intent2Prompt 编译 |
| --- | --- | --- |
| 任务类型识别 | 无 | 自动识别 + 置信度 |
| 缺失信息 | 用户自己不知道漏了什么 | 自动检测 + 显式占位 |
| 角色 / 约束 | 几乎没有 | 角色设定 + 专业约束 |
| 输出结构 | 混乱、随机 | 对标评审 / 转化 / 汇报的标准结构 |
| 防幻觉 | 高风险（AI 自由编造） | 占位 + 强制标来源 |
| 可迭代 | 一次性生成 | 最多 3 条追问引导补全 |
| 质量评估 | 凭感觉 | 7 维度 100 分制可量化 |
| 版本选择 | 只有一个 | 简洁 / 专家 / 比赛项目三版 |

> **一句话结论**：Intent2Prompt 把"写好提示词"从手艺活，变成了一条人人可用的标准编译流水线。
